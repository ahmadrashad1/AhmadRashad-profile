Part A — Foundations03 · Intent
01 — Intent

Why this replaces the clay

The current site is claymorphic: pillowy, rounded, warm-lit, every surface raised off a sage tabletop. It is well built and it is not wrong. It is simply a different argument than the one this system makes.

The argument

Claymorphism says touch this. Bauhaus says this was constructed. For a developer portfolio read by recruiters in seconds, the second claim is the stronger one: it reads as engineering rather than decoration, and it survives being screenshotted, scaled down, and skimmed.

The inversion is total and deliberate. Soft becomes hard. Raised becomes flat. Implied light becomes printed ink. Floating becomes gridded. Nothing is kept because it was expensive to build.

What survives

Three things carry over, because they are identity rather than styling: the bird, the floating field behind the hero, and the avatar. Each is rebuilt from the shape vocabulary on page 10 rather than redrawn soft. See page 18.

Part A — Foundations04 · Principles
02 — Principles

Five rules that settle arguments

Six tiles, one grid, three colors, no gradients. The whole system is visible in this square.

01 — Structure is the decoration

Ornament is never applied on top. A page is decorated by making its grid, its rules and its blocks visible. If you are adding a shape to fill a gap, the layout is wrong.

02 — Color carries meaning, never mood

Red is action. Blue is information and links. Yellow is attention and warning. A shape is colored because of what it does, not because the corner looked empty.

03 — Depth comes from offset, not blur

There are no soft shadows in this system. Where something must sit above something else, it is offset by a hard black block. See page 11.

04 — Geometry is primitive, never custom

Square, circle, half-circle, quarter-circle, right triangle. Every illustration in the product is assembled from these five. No bespoke curves.

05 — One screen, one action

Carried over unchanged from the current product: every view has exactly one primary next step, and only that step wears red.

Part A — Foundations06 · Color rules
03.1 — Application

Where each color is allowed

Red — action

Exactly one red element per viewport. It is the thing you want pressed.

  • Primary button fill
  • The live/online dot
  • Destructive confirm
  • Section kickers (type only)

Never: two red buttons on one screen; red body copy; red as a large background field.

Blue — information

Blue is the reading color. It never competes with red for the click.

  • Every text link
  • Focus ring (3px, offset 2px)
  • Section-break blocks
  • Icon chips and secondary fills

Never: blue on a primary CTA; blue and red touching edge to edge without a black rule between.

Yellow — attention

The smallest-area color. Yellow is a highlighter, not a surface.

  • Callout left bar
  • Current-slide dot
  • Warning / rate-limit state
  • One accent tile per motif band

Never: white text on yellow; yellow as a page background; yellow for a link.

Do

Separate two color fields with a black rule of at least 4px.

Let paper be the dominant area — color is roughly 15% of any screen.

Use ink for every border, regardless of the fill it surrounds.

Don't

Tint, shade or fade any triad color — there is no red-400.

Use color to indicate elevation; that is what offset is for.

Introduce a fourth hue for "just this one chart".

Part A — Foundations08 · Type rules
04.1 — Type rules

How the two faces divide the work

The division

Jost writes sentences. IBM Plex Mono writes values: domains, token names, stack chips, stat counts, credentials, dates, page numbers, every uppercase label.

The test: if you would read it aloud as a phrase, it is Jost. If you would spell it out character by character, it is mono.

Tracking
ContextTracking
Display & h1−0.035em to −0.025em
h2 / h3−0.015em
Body0
Mono labels (caps)+0.14em to +0.22em

Geometric faces get loose at display size and crowded in caps — negative tracking above, positive in caps, nothing in between.

Measure & rhythm
  • Body measure caps at 68ch.
  • Body line-height 1.5; headings 1.05.
  • text-wrap: balance on every heading — carried over from the clay build.
  • Paragraph spacing is one --s3 step, never a blank line.
Do

Set section labels in mono caps, as on page 06.

Let headings run long and wrap — balance handles it.

Don't

Set a heading in mono because it "looks technical".

Use italics. This system has none.

Center body copy. Headings may center; paragraphs never.

Part A — Foundations10 · Shape
06 — Shape vocabulary

Five primitives, nothing else

Every illustration, icon, avatar and decorative tile in the product is assembled from these five forms at a single tile size. There are no bespoke paths and no imported icon sets with their own geometry.

square
circle
half
quarter
triangle
Rotation is the only transform

Each primitive exists in four rotations — 0 / 90 / 180 / 270. Nothing is scaled non-uniformly, skewed, or rotated off a right angle. A quarter-circle is always a true quarter of a true circle.

In CSS they are pure border-radius and clip-path on a square box — no SVG required for any of the five.

Composition

Tiles combine on a square lattice at one of three sizes: 64 / 96 / 128px. Adjacent tiles may share a color; adjacent tiles may not form an accidental third shape that reads as a letter or a face — check every band at thumbnail size.

Tile lattice

Roughly one in four cells stays paper. A fully packed band reads as noise at mobile width.

Part A — Foundations11 · Depth
07 — Rule weight & depth

Offset replaces shadow

The clay build carries a dual soft shadow on every surface, hue-matched to the background. All of it is deleted. Depth in this system is a hard black block offset behind the element — printable, scalable, and honest about being flat.

Rule weights
TokenpxWhere
--bq-rule-hair1Table row divider only
--bq-rule-thin2Chips, inputs, small blocks
--bq-rule-mid4Cards, buttons, the default
--bq-rule-bold8Section rules, callout bars

Every rule is --bq-ink. A colored border does not exist in this system; color goes in the fill.

Offset depth

Two levels, and only two. Resting elements sit flat on the page. Elements that can be pressed carry 4px of offset. Elements floating above the page — dialogs, sheets — carry 8px. Pressing animates the element into its own offset.

The three states
Flat — resting
box-shadow: none
Raised — pressable
box-shadow: 4px 4px 0 ink
Floating — dialog
box-shadow: 8px 8px 0 ink
The one-line test for a correct migration: search the stylesheet for blur and for any box-shadow whose third value is not 0. Both searches must return nothing.

Part B — Components18 · Characters
14 — Characters

The bird, the field, the avatar

These three survive the rewrite because they are the only parts of the site a visitor remembers. Each is rebuilt from the five primitives — constructed, not redrawn soft.

The bird

Circle body, half-circle wing, triangle beak, quarter-circle tail. The wing is the only animated part: it rotates about its flat edge between 0° and −38°.

Scroll-velocity flap mapping is unchanged: 420ms idle down to 90ms at speed, easing back 200ms after scrolling stops.

The floating field

The three drifting clay blobs and four icon chips become one field of primitives in the hero margins.

Critical change: tiles do not drift freely. They translate along one axis only, by at most 8px, on an 8s loop — they must still read as locked to the grid.

The avatar

A square portrait field, not a blob. Hair is a half-circle, eyes are circles, shoulders are a half-circle.

Removed: the pointer-driven rotateX/rotateY tilt and the moving highlight. A flat system cannot fake dimension and should not try.

15 — Motion

Mechanical, not springy

Clay motion overshoots and settles, because clay is soft. Constructed things slide and stop. Every easing in the system is linear or a sharp ease-out — nothing bounces, nothing wobbles.

Card reveal keeps the current build's trick of animating translate rather than transform, so the finished animation's forwards fill does not swallow the hover lift.

Banned
  • Spring and bounce easings
  • Scale on hover
  • Blur transitions
  • Parallax
  • Rotation off a right angle
  • Anything over 450ms except the drift loop
prefers-reduced-motion: drift and flap stop entirely, reveals become instant, the sheet appears without rising. The bird is display:none, exactly as today — skipped outright rather than left to flash past a 0.01ms override.

The breakpoints that already exist

The clay build runs eight breakpoints, several of them keyed to viewport height rather than width. They are load-bearing and they stay — restyling must not quietly collapse them into a tidy three-tier set.

Height queries are not decoration. The hero is a locked viewport; a laptop at 1440×720 clips without the max-height rules. Test landscape phones explicitly — they have side margin and no vertical slack, the opposite shape from portrait, and are deliberately excluded from the tall-phone tier.
Rule weights scale down. Below 640px, --bq-rule-bold drops 8px → 6px and --bq-rule-mid 4px → 3px. At phone width an 8px border eats the content area; the grid should look the same weight relative to the screen, not absolutely.

Part C — Application23 · Accessibility
18 — Accessibility

What flat buys, and what it costs

What it buys
  • Every border is ink on paper — 15.6:1. Component edges are unmissable.
  • No shadow means no low-contrast surface boundary, the usual neumorphism failure.
  • Hard offsets survive Windows High Contrast Mode, which strips box-shadow blur.
What it costs
  • Red on paper is 3.4:1 — large text only, never a paragraph, never a caption.
  • Red and blue at equal weight are hard for deuteranopia: never pair them as the sole difference between two states. Shape or label must also differ.
  • Flat removes the depth cue for "pressable". The 4px offset is doing that job alone, so it may never be dropped for aesthetics.
Requirements
AreaRequirement
Focus3px blue outline, 2px offset, radius 0, on every interactive element
Target size≥44×44px
MotionFull prefers-reduced-motion path
DecorationEvery tile and character aria-hidden="true"
DialogsNative <dialog> — focus trap, Escape, focus return
ImagesAlt text describes the screen, not "screenshot"
ContrastWCAG AA minimum, verified per combination
Focus rings are square. The clay build sets a border-radius on :focus-visible to match rounded components — that declaration must be removed, or every focus ring in the new system renders with soft corners against hard ones.

Part C — Application25 · Do & don't
20 — Do & don't

The page to re-read before shipping

Do

Let the grid show. Visible structure is the decoration; a rule is never apologised for.

Keep paper dominant. Color covers roughly 15% of any screen.

Build illustrations from the five primitives, at right angles only.

Use offset for depth, at exactly 4px or 8px.

Set values in mono, sentences in Jost.

Keep one red element per viewport, and make it the thing you want pressed.

Preserve every dialog mechanism — only the skin was in scope.

Re-measure the bird's sheet overlap after restyling, by rect, at each breakpoint.

Don't

Don't leave a blurred shadow anywhere. One survivor undoes the system.

Don't round a corner — not on a focus ring, a badge, an avatar, or a dot.

Don't tint a triad color. There is no lighter red.

Don't add a fourth hue for a chart, a tag, or a state.

Don't fill a gap with a shape. If the corner looks empty, fix the layout.

Don't bounce. Constructed things slide and stop.

Don't collapse the height-based breakpoints into a tidy width-only set.

Don't centre body copy. Headings may; paragraphs never.
